# 输出形式说明（Step 6.7.4 依据）

三种形式对应不同使用场景，用户可多选。所有形式以同一份 Markdown 为中间产物，
保证内容一致；再按需转 docx / 重组为 HTML。

## 三种形式对比

| 形式 | 文件后缀 | 适合场景 | 特点 |
|---|---|---|---|
| 1. 详细 Word | .docx | 正式存档、提交 OA/归档、发给不熟 HTML 的同事 | 可编辑、排版正式、含完整 30 条 QA 与全部细节 |
| 2. 可视化 HTML | .html | 发群里/给客户看、快速浏览 | 卡片式版式，自带右下角导出按钮（PDF/PNG/JPG），浏览器打开即用，无需 Office |
| 3. Markdown | .md | 贴进飞书文档/企微/Notion/知识库 | 最轻量，纯文本可编辑，直接粘贴 |

## 选择建议（给用户推荐时用白话）

- **存档/提交** → 选 1（Word）
- **分享/展示** → 选 2（HTML），最好看
- **要进公司知识库/文档平台** → 选 3（Markdown）或把 HTML 内容贴入
- **不确定** → 默认 1+2（Word 存档 + HTML 分享），成本最低覆盖最全

## 生成要点

### 形式 1：Word（docx）
1. 先产出 Markdown 成品。
2. 优先走本地 Office 通道创建 docx 并写入 Markdown 正文（标题层级、表格、加粗
   自动转排版）；编辑器通道不可用时，用 python-docx 兜底生成（设置标题样式、
   表格边框、加粗，保证可读）。
3. 文件名：`{主题}_会议纪要.docx`，放 `outputs/`。

### 形式 2：可视化 HTML
1. 复制 `references/visual_template.html` 的骨架（head 样式 + 导出栏 + 导出脚本
   必须原样保留）。
2. 只重写 `#capture` 容器内的**正文区**：把本次纪要内容按模板示例的区块模式
   （Header + 关键决议 + 分主题卡片网格 + 流程时间线 + 总结建议）重组。
3. 内容精炼原则：每张卡片只放最要点（3-5 条 bullet），完整细节留在 Word/Markdown；
   QA 只挑 3-5 条高频的进 HTML，其余注明"完整 QA 见配套 Word 纪要"。
4. 文件名：`{主题}_可视化纪要.html`，放 `outputs/`。
5. 区块配色约定（与模板一致，保持品牌统一）：
   - 监管/规则类 section → 紫色系
   - 宣传/流程类 section → 青色系
   - 新规/门槛类 section → 粉色系
   - 计划/时间线类 section → 琥珀色系
   - 总结/建议类 section → 蓝色系
6. 导出按钮说明（已在模板中实现，勿删）：
   - 导出 PDF：`window.print()`，配 `@media print` 强制保留背景色
   - 导出 PNG/JPG：html2canvas 1.4.1 截图 `#capture`，scale=2
   - 依赖 cdnjs 的 html2canvas，需联网；PDF 不依赖网络

### 形式 3：Markdown
1. 即 7.1 通用结构的成品 .md 文件，无需转换。
2. 文件名：`{主题}_会议纪要.md`，放 `outputs/`。
